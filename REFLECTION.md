##Question 2 - Trace a many-to-many relationship. Identify a many-to-many or association-table relationship in your ATS. Explain which models are connected and why a single foreign key would not represent the relationship correctly. Identify the association table or model and explain whether Django created it automatically or your project defines it explicitly. If it is an explicit association model, explain what data belongs to the relationship itself.

# Focusing on the many to many relationship between 'Candidate' '@hiring/models.py line 7' and 'JobOpening' '@hiring/models.py line 63' through 'Application'. A 'ForeignKey(JobOpening)' on 'Candidate' wouldn't be able to represent the relationship because then each candidate could only have one opening to apply to, so a candidate applying for another job would overwrite the other, if you did it the other way around, giving the 'ForeignKey(Candidate)' to 'JobOpening' causes the same error but reverse, each job could only have one person apply to it. This is why we have a many-to-many so both sides link to eachother through the association model 'Application' '@hiring/models.py line 114' which was defined in the '@project-idea.md' line 11 which defined the relationships being "A candidate may apply for several different jobs, but should not have more than one application for the same opening." .It express the many-to-many relationship by having two foreign keys connecting each side to their main model. With constraints that make sure a candidate can apply to an opening only once, but they can have multiple openings they apply to. Why the data belongs to the Application relationship as it's explicit model is because certain facets of the relationship, like the scenario above describe a candidates specific application to an opening rather than just the candidate and openings alone.
